# Executed upstream numerical validation

The Python group-prior estimator agrees with executed CBIG MATLAB equations
on four deterministic synthetic fixtures, including float32 production input,
missing sessions, zero-profile vertices, and uncertain posteriors. Labels are
compared in their original network order: no permutation or relabeling is
allowed. This establishes agreement for these numerical cases. It does not
establish equivalence of human parcellations, preprocessing, mesh assets, or
the complete MATLAB workflow.

## Sources and runtime

The workflow reference is Buckner PrecisionNetworkMapping commit
`988ec48cf5453c6009a6f82dbddf5d5b99eda3cd`. Its executable training script calls
CBIG group estimation with a maximum of five outer iterations and extracts
the resulting subject posteriors; it does not perform an additional individual
MRF fit. The numerical source is CBIG commit
`35b5664bec8822e2f77da5e090e96f91d0095be6`.

Unchanged source files are bundled under `validation/upstream/`. CBIG's MIT
copyright and permission notice are in `LICENSE-CBIG.md`; the bundled
`mtimesx_upstream.c` retains James Tursa's BSD notice. These files retain their
original authorship and licenses. Source paths are:

- `stable_projects/brain_parcellation/Kong2019_MSHBM/step2_estimate_priors/CBIG_MSHBM_estimate_group_priors.m`
- `utilities/matlab/stats/CBIG_nansum.m`, `CBIG_nanmean.m`, and `CBIG_corr.m`
- `utilities/matlab/FC/CBIG_ComputeCorrelationProfile.m`
- `stable_projects/brain_parcellation/Xue2021_IndCerebellum/CBIG_IndCBM_generate_MSHBM_params.m`
- `external_packages/matlab/default_packages/mtimesx_20110223/mtimesx.c`

Execution used GNU Octave 6.4.0 (`6.4.0-2`) and Debian BLAS
`3.10.0-2ubuntu1` inside an amd64 Ubuntu 22.04 Podman container on Apple
Silicon. The image digest and package details are recorded in
`validation/fixtures/runtime-environment.json`. Each oracle manifest records
SHA-256 checksums of the source, numerical adapter, helper adapters, and NPZ
fixture. Tests check these hashes before accepting the reference.

## Adapter boundaries

`generate_reference.py` extracts contiguous initialization, EM, and local
function sections from the original estimator. The executed equations,
concentration floors, stopping conditions, and single-precision casts remain
unchanged. Its infrastructure adaptations are:

1. Supply deterministic arrays and the same scalar settings instead of
   `internal.stats.parseArgs`, MRI/mesh reads, and project-directory setup.
2. Omit upstream output saves and path changes; save the returned structure
   in an Octave-compatible MAT file.
3. Replace the unavailable `mtimesx` MEX with explicit page matrix products.
   The pinned C implementation, lines 755–756 and 783–784, casts the double
   matrix to single before multiplication if either non-scalar matrix is
   single; line 1391 specifies single output. The adapter preserves both
   operand and result precision. Existing double fixtures were re-executed
   after verifying this behavior; the float32 fixture uses the same adapter.
4. Catch Octave's `fzero` scalar-bracket failure and return an unsuccessful
   exit flag. This does not change `invAd`'s returned value: the upstream
   function declares output `outu` and returns that initial approximation,
   independently of the subsequently computed `out`/root. Other solver
   exceptions still propagate.

The adapter is not a separate Python translation of the equations. The
reference fixture is generated by executing the extracted upstream source;
the Python implementation is invoked only during comparison. Octave and
MATLAB can still differ in library arithmetic and platform behavior.

## Cases and measured results

The four EM cases use 300 vertices, 101 profile features (vMF dimension 100),
three subjects, two sessions, three networks, random seed 73619,
`epsilon=1e-4`, `conv_th=1e-5`, concentration floor 500, and a maximum of five
outer iterations. Profiles are mean-centered and unit-normalized, with two
zero rows. Case modifications are deterministic and implemented in the
generator:

| Case | Input | Python / Octave stopping iteration | Label mismatches |
| --- | --- | --- | --- |
| complete | float64, all sessions | 4 / 4 | 0 |
| missing | Subject 3, session 2 is all NaN | 5 / 5 | 0 |
| soft | Two identical template directions produce 0.5 posteriors | 4 / 4 | 0 |
| single | Same normalized profiles converted to float32 | 4 / 4 | 0 |

Every case compares `mu`, `epsil`, `sigma`, `kappa`, `theta`, `s_psi`,
`s_t_nu`, `s_lambda`, `cost_em`, `cost_intra`, `cost_inter`, and the entire
outer cost record. Matching missing-session NaNs are required at the same
locations. Observed maximum direction errors are below 1.3e-7; maximum
concentration relative error is below 5.6e-6. Cost-record absolute errors are
at most 0.0625 (relative error below 2.4e-7). The complete and float32 cases
have posterior errors below 8e-14; soft-case posteriors match exactly.
Exact per-case errors, thresholds, execution times, and pass/fail results are
stored in `validation/fixtures/convergence-report*.json`.

The comparison tolerances are fixed in `compare_reference.py`: direction
arrays use `atol=2e-5, rtol=1e-4`; posteriors and spatial priors use
`atol=rtol=1e-4`; concentrations use `atol=.05, rtol=2e-4`; costs use
`atol=.1, rtol=5e-6`. The float32 case uses the existing tolerances without
widening them. Labels and the outer stopping iteration must match exactly.

The separately executed profile oracle uses original CBIG correlation,
global top-10% threshold, normalization, and label-centroid equations.
Inputs include full and partial NaNs at medial-wall vertices and a
nonconstant profile containing an exact centered zero. Binary profiles and
normalization match exactly; centroid maximum absolute error is 2.3e-16 or
less. See `profile-convergence-report.json` and `profile-provenance.json`.

An additional portable fixture captures the intra-subject state from a
deterministic full-surface synthetic smoke run. Quantized unit directions can
yield a resultant slightly above one and an intermediate negative sigma.
Executing the original isolated intra-subject routine confirms convergence
after two iterations using its raw signed denominator, followed by positive
sigma. The diagnostic adapter adds a 10,000-iteration guard, which was not
reached. This stage is tested separately in `test_reference_intra_boundary.py`;
it is not an end-to-end surface oracle.

## Reproduction

With the project environment installed, compare the portable fixtures without
MATLAB, Octave, a container, or downloaded scientific assets:

```sh
python -m pytest tests/test_reference_oracle.py tests/test_reference_profiles.py tests/test_reference_intra_boundary.py -q
python validation/compare_reference.py --case complete
python validation/compare_reference.py --case missing
python validation/compare_reference.py --case soft
python validation/compare_reference.py --case single
python validation/compare_profiles.py
```

With Octave available locally, regenerate source outputs and manifests:

```sh
python validation/generate_reference.py --case complete
python validation/generate_reference.py --case missing
python validation/generate_reference.py --case soft
python validation/generate_reference.py --case single
python validation/generate_profile_reference.py
```

Alternatively, create an ephemeral Octave container (the repository's parent
must be mounted at `/work`, with this checkout named `pyMSHBM`):

```sh
podman run --platform linux/amd64 --name pymshbm-oracle -d -v "$PWD/..:/work" ubuntu:22.04 sleep infinity
podman exec pymshbm-oracle sh -c 'apt-get update && DEBIAN_FRONTEND=noninteractive apt-get install -y --no-install-recommends octave'
python validation/generate_reference.py --podman-container pymshbm-oracle --case single
```

The generator accepts `--prepare-only` and `--collect-existing` to split
preparation, reference execution, and fixture packaging. For example, after
preparing a case, execute:

```sh
podman exec pymshbm-oracle octave --quiet --eval "addpath('/work/pyMSHBM/validation/runtime'); run_oracle_case('/work/pyMSHBM/validation','single');"
python validation/generate_reference.py --case single --collect-existing
```

Generated MAT transport files are ignored; NPZ fixtures and manifests are
portable and retained. Re-running may produce different archive/checksum
metadata or minor floating-point differences across BLAS versions. Review
the regenerated source outputs and comparisons together before replacing a
checked-in fixture.

## Limits

These are numerical kernel tests using synthetic data. They do not test
denoising equivalence, fsaverage registration, interpolation, asset-version
equivalence, temporal censoring, fMRIPrep vs Buckner preprocessing, or
scientific accuracy on human data. The full-surface smoke run exercises the
Python workflow but is not an upstream full-surface comparison. The group
fixtures do not exercise vMF dimension 1200 or higher, and their shared
inter-region concentration remains at the source floor. No conclusion about
other parameter regimes follows from these cases.

During fixture design, smaller/noisier or nearly identical-session examples
produced concentrations around 1e11–1e14 and unstable cost trajectories in
the upstream implementation itself. The final EM fixtures retain finite,
well-conditioned concentrations so continuous differences can be measured;
they do not establish equivalence at singular concentration limits. The
separate captured-stage boundary test covers one observed near-unit
resultant, not every degenerate configuration. A pinned MATLAB run on an
authorized human dataset with matching preprocessing and mesh assets remains
necessary before claiming full scientific convergence.
